## 6. Current Starter Architecture

The v2.5 Starter is an Astro static site:

- `astro.config.ts` sets `output: "static"` and `trailingSlash: "always"`.
- Runtime Page Inventory is the publication SSOT in `src/data/page-inventory.json`, parsed by `src/data/schemas/page-inventory.ts`.
- Enabled pages are derived by `src/core/catalog.ts` from visibility, publication status, and feature flags.
- `src/core/site-data.ts` centralizes parsed config, parsed inventory, enabled catalog, navigation resolution, and page lookup.
- Route families are explicit under `src/pages/*`; there is no generic root catch-all.
- Content, facts, config, media, navigation, and theme are separate modules.
- `StaticWikiPage.astro`, `WikiArticle.astro`, homepage, and entity shells have fixed media placements rather than a page builder or DSL.

## 9. Current Media Audit Behavior

Two audit layers matter:

- `src/core/html-audit.ts`
  - `collectBuildHtmlAuditErrors(...)` audits SEO, canonical, robots, H1, Pagefind, JSON-LD, image `alt`, internal links, duplicates, and orphaned routes.
  - It checks all `<img>` tags only for existence of `alt`, regardless of media role.
  - `collectReferencedAssetPaths(html)` collects only `/_astro/` build assets, not `/media/` or `/favicon.svg`.
- `scripts/media-validation.ts`
  - `collectMediaHtmlErrors(...)` iterates every rendered `<img>` in a page and fails any image whose `src` is not an existing local media file under `/media/`.
  - It then separately validates `figure[data-media-id]` against the manifest asset list and expected page placement mapping.
  - It iterates every `<iframe>` and only accepts registered YouTube-nocookie embeds.

Important behavior:

- Empty no-media pages pass `collectMediaHtmlErrors("<main>Text only</main>", [], ...)`.
- Any semantic header logo such as `<img src="/logo.svg" alt="Game Name">` or `<img src="/brand/logo.svg" alt="Game Name">` would fail media audit because the audit treats every page `<img>` as content media under `/media/`.
- A header logo under `/media/logo.svg` would pass the broad local path existence check, but if it is not wrapped as `figure[data-media-id]` it is not semantically validated as content media. That would blur roles rather than fix them.

## 11. Exact Technical Root Cause Of Logo Defect

Root cause:

`collectMediaHtmlErrors` in `scripts/media-validation.ts` validates every `<img>` tag on a generated page as if it were content media. Its first image loop fails any image not under `/media/` or missing from the build output media directory. The function has no role boundary for site chrome assets and no way to exempt or separately validate header logo, favicon, brand mark, footer mark, or decorative UI assets.

This is not an accessibility issue in `html-audit.ts`; that file correctly requires `alt` on all images. The production defect is a role classification issue in content-media validation.

## 12. HIGH PRIORITY Media Readiness Surface

Current v2.5 has no planning-state contract for media need, candidate, rights, human decision, integration, or visual gate. That absence is intentional in v2.5 and protected by SOP/Master Prompt:

- SOP v2.6 says Runtime Page Inventory must remain publication SSOT and must not receive media/layout fields.
- SOP v2.6 places route-level media lifecycle in `MEDIA_DECISION_TABLE.md`, not Runtime Page Inventory.
- Master Prompt v2.6 says Starter technical behavior owns media manifest/rendering; it does not own rights, Human decisions, or workflow state.

Smallest technical surface:

- Add a lightweight optional planning input reader/validator for `MEDIA_DECISION_TABLE.md` if present.
- Key rows by Page Inventory `pageId` or route.
- Emit validation signals for unresolved high-priority media without moving lifecycle ownership into runtime publication data.
- Preserve no-media validity when the planning table explicitly says `NO MEDIA NEEDED` with rationale.

This should live near validation scripts, not inside `src/data/schemas/page-inventory.ts`.

## 13. Current Third-Party Video Behavior

Current reusable behavior:

- YouTube is represented in the media manifest as a canonical 11-character ID.
- `VideoEmbed.astro` renders `youtube-nocookie.com/embed/...` iframe with title, lazy loading, constrained permissions, fullscreen, and referrer policy.
- `collectMediaHtmlErrors` validates iframe source, title, loading, allow/fullscreen, privacy contract, and wrapper.

Current missing behavior:

- No visible fallback content is rendered inside or around the iframe for blocked/lazy/unpainted third-party player states.
- No test simulates or asserts the Afterworld blank player failure state.

Decision evidence:

- SOP requires an intentional visible fallback where a third-party media failure would look broken, but also states the SOP owns the quality expectation, not a specific component implementation.
- Master Prompt says third-party fallback states should be covered where implemented, and project-specific repeated gaps should not be backported automatically from one project.
- One successful project-edge fallback exists, but the v2.5 Starter already has a valid narrow YouTube contract. More than one production project would provide stronger proof before enlarging Stable Core.
